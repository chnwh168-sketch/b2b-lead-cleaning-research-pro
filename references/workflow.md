# 批次流程与状态控制

## 0. 输入与运行清单
保存源文件 SHA-256、工作表/列/行数、来源渠道、时区、研究时间、产品线及已同意 P1–P4 示例、CRM profile、邮件策略和输出位置。创建 Source_Row_ID（文件哈希前缀+表名+原行号），保留原行号。询盘/截图保留原文和来源引用，无法辨认的字段不猜。
每行标记正常、空白、格式异常、缺少买方等处置；即使不是候选也在审计中保留。金额按币种分组，数量按单位分组；没有换算依据不得直接相加。日期范围属于源数据覆盖，不是企业全历史。

## 1. 两种入口
海关：按完整描述、品牌和型号判 P1 明确目标、P2 很可能、P3 大概率相邻非目标、P4 明确非目标。HS 仅辅助。P1+P2+P3+P4+异常=原交易行数。只提取 importer/buyer/consignee；supplier/exporter 保留作证据。P3 默认待复核，P4 可排除；有其他可信匹配交易的公司不随单条 P4 排除。
一般名单/询盘：保留每个联系人、问题、产品/型号/数量、目的地、预算、时间、平台和沟通历史。没有交易描述时 P 分类留空，不强套海关规则。明确询盘产品优先于推断产品。

## 2. 实体与冻结
保守规范名称和电话；不同国家、税号、法律形式不得仅凭相似名称合并。按确证法律实体聚合交易；联系人用 Contact_ID 关联 Company_ID，独立保留。源事实没有身份闭合时维持临时实体并标复核。
CRM 连接器可用时查精确邮箱、精确电话及上下文；只读查询不意味着授权更新。精确联系方式可为共享联系方式，核对具体主体与人员。名称/域名相似只作软信号。
冻结 frozen_company_ids.json（唯一 ID 数组）、company_master、source_to_company、alias_map、规则版本和各类计数。后续别名合并保留从 ID，在第三表写 Master Company_ID。新增拆分或误分类修正通过新冻结版本，记录 old→new、原因、证据和数量变化，重跑交付核对。

## 3. 研究：三轮及针对性复核
逐公司保存研究状态 Pending/In Progress/Complete/Blocked、各轮查询和来源、日期及未解决事项。Complete 表示已完成约定范围，不表示所有信息都找到。
第一轮身份：公司+国家城市、邮箱、域名、电话、官网、官方社媒、登记信息；至少两项有效信号闭合主体，姓名还要闭合所属与角色。
第二轮经营：官网产品/服务/联系/团队/分支页、近期官方活动、登记状态、库存/租赁/维修/代理/项目。超过24个月的材料独自不足以证明当前经营；官网打不开独自不足以证明停业。
第三轮采购渠道：优先近6–18个月采购、进口、重复订单、中国供货、供应商、数量金额、品牌授权、OEM、库存及售后。详细记录交易日期/产品/供应商/金额/数量/来源/覆盖范围。数据库显示次数不能当全历史总进口。
P2 复核为 P2-A 确认、P2-B 高概率、P2-C 未解、P2-D 确认非目标。P2-C 保留复核；若主体闭合且其他证据足以支持商机，可 Include 并标风险，否则 Manual Review。P1 证明源数据中发生过采购，不自动证明当前经营或渠道角色。
普通线索三轮后在关键问题回答或检索预算耗尽时停止。潜在 A、具体 RFQ、高优先级无官网、无可用联系方式、P2-C、不匹配、重复或身份冲突加一次定向复核；不无限重复相同查询。阻断需列明工具/登录/站点限制和可继续事项。

## 4. 联系与评分
即使已有电话/WhatsApp，也查找邮箱。官网→官方社媒/文件→政府协会代理目录→可信本地目录；平台自己的电话邮箱不可移植给客户。联系人优先采购、负责人、运营设备租赁维护工程，再用公司邮箱。
写证据账本及 scoring.md 的独立结论。没有官网但目标采购和身份可信，可 Include；低优先级不等于排除。严重身份冲突或未闭合主体进入 Manual Review。明确物流中介须排查其是否也是实际买方。

## 5. 邮箱门槛
保存所有候选及归属、用途、来源，去重生成 email-only CSV 和 company/contact→email 映射。完整研究前不把优先子集核验当最终验证。默认只用本批次最终任务，保存哈希、任务 ID、报告、完成状态及集合对账。用户尚未授权消耗额度时交付无邮箱草稿与候选审计，明确验证待完成，不称最终带验证版。
零候选：不调用验证 API，任务状态 Skipped-No Candidates、task ID 留空；第一表空表仍含表头，其他表照常交付。

## 6. 决策与交付
Include：主体可靠且有可信目标/相邻需求、采购或具体真实询盘机会；无官网、无联系人不单独排除。
Exclude：确认无关、非买方、永久注销且无有效承接主体等；Merged 从记录保留 Exclude 并映射主记录。
Manual Review：严重身份冲突、未确认主体、无足够证据的 P2/P3 等。不得以未搜索到资料伪装成负面证据。
三表逐 ID 对 frozen_company_ids.json 核对；来源→实体→主从映射必须闭合。JSON 联系人数量可能大于公司数，不参与公司三表计数。保留原顺序和 sidecar input/output ID 映射。
生成摘要、来源与风险、检查报告、研究覆盖统计；有 Blocked/Pending 明确为阶段性成果。所有检查通过后复制至指定目录并校验 SHA-256。
